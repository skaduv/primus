# 安装测试清单（MSI · 干净 Windows 11 虚拟机）

对应技术方案第 3 章（安装包）、第 4 章（数据目录）、第 23 章（安装测试：干净的 Windows 11 虚拟机快照，发布前执行）。
第 1 节开始前用 `scripts/vm/Reset-PrimusTestVM.ps1` 把虚拟机还原到 `clean` 检查点；第 1–5 节是同一次安装的连续步骤，
中途不要还原（还原会回到未安装状态，第 2–5 节将必然失败）。之后的大项若需要干净环境，还原后先按第 1 节重新安装 MSI 再继续；
虚拟机的准备与脚本用法见 [scripts/vm/README.md](../scripts/vm/README.md)。

复制本文件为 `安装测试记录-<版本>-<日期>.md` 后逐项勾选；不通过的项在行尾写现象，并附上收集的日志（第 12 节）。

## 自动化安装矩阵（CI）

推送 `dev` / `main` 时，CI 的 `install-matrix` 作业对刚构建的 MSI 自动执行 P0 安装矩阵：x64 与 ARM64 ×
Program Files、隔离的非系统 NTFS 卷两个位置。后者始终新建 VHDX，优先 `D:\primus`；运行器已有 D 盘时选择其他空闲盘符，绝不修改现有盘的所有者或 ACL。每格覆盖第 1 节（静默安装、布局）、第 4 节（Core 进程，用安装后的运行时完成
含工具调用的对话；x64 另经端到端测试在界面上完成对话）、第 5 节（新建**标准用户**启动 App、`users\<SID>` 所有者与 ACL、
读不了其他用户的目录、写不进安装目录根）、第 9 节（卸载后 data 保留），并确认数据都在 `<安装目录>\data`（用户主目录无 `.primus`，
`%APPDATA%` / `%LOCALAPPDATA%` 无 `com.primus.desktop`）。日志在作业的 `install-matrix-<架构>-<位置>` 产物中。
模型用本机 Faux 服务，不需要密钥。以下手工项（向导界面、开始菜单、升级、修复、WebView2 缺失、SmartScreen 等）仍按清单执行。

## 1. MSI 安装

- [ ] 双击 MSI：显示中文安装向导与许可页，许可文本完整可读
- [ ] **默认目录**：安装位置显示 `C:\Program Files\Primus\`，一路下一步完成，无报错
- [ ] UAC 提示中的发布者名称（已签名时为证书主体；未签名时为「未知发布者」，记录在第 10 节）
- [ ] 安装后目录含 `Primus.exe`、`PrimusUpdate.exe`、`resources\runtime\node.exe`、`resources\runtime\LICENSE`、
      `resources\agent-core\`（含 `rpc-entry.js`、`manifest.json`、`LICENSE`、`extensions\primus-bundle.js`）、`data\`
- [ ] 「设置 → 应用 → 已安装的应用」中出现「乾元 Primus」，发布者、版本、图标正确
- [ ] `services.msc` 中有「乾元 Primus 更新服务」（PrimusUpdate）：启动类型「手动」，登录身份「本地系统」，状态未运行；
      `sc.exe sdshow PrimusUpdate` 中交互用户（IU）只有 `CCLCSWLORPRC`；`HKLM\SOFTWARE\Primus` 的 `Version` 为本版本；
      `%ProgramData%\Primus\Update` 存在，所有者 SYSTEM，只有 SYSTEM 与 Administrators 有权限（不继承）
- [ ] **自定义目录（中文与空格）**：还原快照后重新安装，在向导中改为 `C:\测试 目录\乾元 Primus\`，安装成功、
      上述文件齐全；可再测一次非系统盘（如 `D:\Apps\乾元 Primus\`，虚拟机需有第二块盘）
- [ ] 静默安装：`msiexec /i <msi> /qn /l*v install.log INSTALLFOLDER="C:\测试 目录\乾元 Primus"` 退出码 0

## 7. 升级（高版本 MSI 覆盖安装）

- [ ] 先装旧版本，启动一次并新建会话（让 `data` 中有设置与会话数据），在 `data` 中另放一个标记文件
- [ ] 直接运行**高版本** MSI（不先卸载）：顺利完成，「已安装的应用」中只剩一个条目且版本为新版本
- [ ] 安装目录中的程序文件为新版本（`Primus.exe` 属性 → 详细信息 → 文件版本）；旧版本独有的文件已移除
- [ ] **data 保留**：标记文件、设置、会话记录仍在，App 启动后能看到之前的会话
- [ ] 自定义目录（含中文与空格）安装的旧版本升级后仍在原目录，不会改装到默认目录
- [ ] 降级：已装新版本时运行旧版本 MSI，被阻止并显示中文提示「已安装更新版本的乾元 Primus……」
- [ ] **从旧 NSIS 版迁移**（还原快照后先装 0.0.8 的 `Primus_0.0.8_<arch>-setup.exe`，启动一次并放标记文件）：运行新版本 MSI，
      向导默认目录为 NSIS 版的目录；安装完成后「已安装的应用」只剩 MSI 条目，`uninstall.exe` 与 NSIS 的开始菜单项已删除，
      `data` 与标记文件仍在、App 能看到之前的会话；`HKLM\SOFTWARE\乾元 Primus\Primus` 已删除
- [ ] 改动 NSIS 安装目录的 ACL（例如给 Users「修改」）后再运行 MSI：安装失败回滚，日志中有 `primus-remove-nsis: error`，没有运行 `uninstall.exe`

### 7.1 应用内自动更新与更新服务（第 3.6 节、ADR 0007）

前提：两个用同一套 updater 密钥构建、都带更新服务的版本（旧版本编译时带 `TAURI_SIGNING_PUBLIC_KEY`），公开仓
`skaduv/primus-releases` 的 `update-feed` 或调试构建的 `PRIMUS_UPDATE_ENDPOINT` 指向新版本清单。x64 / ARM64 各做一遍，管理员账户与**标准用户**账户各做一遍。
CI 已用 `scripts/update-service-smoke.ps1` 自动覆盖服务侧（错签、降级、程序运行中 / 已退出、卸载清理）；这里验证真实 App 与交互会话。

- [ ] 设置 → 更新：显示当前版本，「自动更新」默认打开，通道为稳定版
- [ ] 打开旧版本约 10 秒后自动下载，右下角提示「Primus x.y.z 已下载并校验，重启即可更新」；
      `data\users\<SID>\updates\` 中有安装包与 `pending.json`，该目录 ACL 只有当前用户与 SYSTEM 可写、Administrators 只读
- [ ] 「立即重启更新」：**不弹 UAC**，Primus 退出，约半分钟内静默装好并以当前用户身份自动打开新版本；任务管理器「详细信息」
      中新 `Primus.exe` 的用户名为当前用户、「已提升」为「否」；`%ProgramData%\Primus\Update\service.log` 记录接受请求、
      msiexec 成功与重新打开，`msiexec.log` 为本次详细日志，暂存的 `package.msi` 已删除
- [ ] 「下次启动时更新」后从托盘退出：**不弹 UAC、不重新打开**，稍后「已安装的应用」中版本已是新版本；再打开 Primus 即为新版本
- [ ] 下载后不点提示，直接退出 Primus：同上，退出时静默安装、不重新打开
- [ ] 有运行中的 Agent 时退出：不安装（留到下次）；点「立即重启更新」先弹确认框，确认后停止 Agent 并静默更新
- [ ] 另一个 Windows 用户同时开着 Primus 时点「立即重启更新」：提示「其他 Windows 用户正在使用 Primus……」，本机 Primus 不退出、待装包保留；
      退出时也不安装（`updates\updater.log` 有记录）；另一个用户退出后，再退出或重新打开 Primus 即静默更新
- [ ] 停用服务（`sc.exe config PrimusUpdate start= disabled`）后「立即重启更新」：回退到 UAC（msiexec 被动安装）→ 新版本以普通权限打开；
      UAC 点「否」：App 继续运行，待装包保留；停用服务时退出 Primus 不弹任何提示，留到下次启动（启动时同样回退到 UAC）
- [ ] 篡改 `updates\` 中的安装包后点「立即重启更新」：拒绝安装、待装包被删除（`updates\updater.log` 有记录）
- [ ] **data 保留**：更新前后会话、设置、标记文件都在；自定义目录安装的仍在原目录
- [ ] 关闭「自动更新」后重启：不再自动下载，退出时也不安装；「立即检查」仍可用

## 12. 日志收集位置

| 日志 | 位置 | 说明 |
| --- | --- | --- |
| MSI 详细日志 | 自行指定：`msiexec ... /l*v <路径>`；msi-smoke 默认 `%TEMP%\primus-msi-smoke\`，经 Reset 脚本执行时为 `C:\PrimusTest\logs\msi-smoke\` | 安装 / 升级 / 修复 / 卸载失败时最关键，搜索 `Return value 3` |
| 冒烟控制台输出 | `C:\PrimusTest\logs\msi-smoke\console.log`（Reset 脚本拉回到宿主机 `vm-logs\<VM>-<时间>\guest-logs\`） | msi-smoke 每一步的检查结果 |
| 薄壳日志 | `<安装目录>\data\shared\logs\app-<日期>.log` | 进程启停、错误、命令耗时（技术方案第 19 章） |
| Core 诊断输出 | `<安装目录>\data\shared\logs\core-<会话>-<日期>.log` | Core 的 stderr |
| 崩溃转储 | `<安装目录>\data\shared\crash\` | App 崩溃时生成 |
| 系统事件 | 事件查看器 → 应用程序（来源 `MsiInstaller`、`Application Error`） | 安装器与进程崩溃的系统记录 |
| WebView2 引导 | `%TEMP%` 下的 `MicrosoftEdgeUpdate*.log`（SYSTEM 运行时在 `C:\Windows\Temp`） | WebView2 安装失败时查看 |

`Reset-PrimusTestVM.ps1` 会自动拉回前两项与 `data\shared\logs`（存在时）；其余手工复制到记录目录。
