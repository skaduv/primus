# 安装测试清单（MSI · 干净 Windows 11 虚拟机）

对应技术方案第 3 章（安装包）、第 4 章（数据目录）、第 23 章（安装测试：干净的 Windows 11 虚拟机快照，发布前执行）。
每个大项开始前用 `scripts/vm/Reset-PrimusTestVM.ps1` 把虚拟机还原到 `clean` 检查点，保证互不影响；
虚拟机的准备与脚本用法见 [scripts/vm/README.md](../scripts/vm/README.md)。

复制本文件为 `安装测试记录-<版本>-<日期>.md` 后逐项勾选；不通过的项在行尾写现象，并附上收集的日志（第 12 节）。

## 0. 测试信息

- [ ] 版本号 / MSI 文件名：`Primus_<ver>_x64_zh-CN.msi`，SHA-256 与发布产物的 `.sha256` 一致
- [ ] 虚拟机：Windows 11 版本号（`winver`）______，检查点 ______，WebView2 运行时：有（版本 ______）/ 无
- [ ] 测试账户：本地管理员 ______；另建一个**标准用户**账户 ______（第 4、5 节需要）
- [ ] 自动化冒烟：`Reset-PrimusTestVM.ps1 -RunSmoke` 通过（附 `console.log`），或说明未执行原因

## 1. MSI 安装

- [ ] 双击 MSI：显示中文安装向导与许可页，许可文本完整可读
- [ ] **默认目录**：安装位置显示 `C:\Program Files\Primus\`，一路下一步完成，无报错
- [ ] UAC 提示中的发布者名称（已签名时为证书主体；未签名时为「未知发布者」，记录在第 10 节）
- [ ] 安装后目录含 `Primus.exe`、`resources\runtime\node.exe`、`resources\runtime\LICENSE`、
      `resources\agent-core\`（含 `rpc-entry.js`、`manifest.json`、`LICENSE`、`extensions\primus-bundle.js`）、`data\`
- [ ] 「设置 → 应用 → 已安装的应用」中出现「乾元 Primus」，发布者、版本、图标正确
- [ ] **自定义目录（中文与空格）**：还原快照后重新安装，在向导中改为 `C:\测试 目录\乾元 Primus\`，安装成功、
      上述文件齐全；可再测一次非系统盘（如 `D:\Apps\乾元 Primus\`，虚拟机需有第二块盘）
- [ ] 静默安装：`msiexec /i <msi> /qn /l*v install.log INSTALLFOLDER="C:\测试 目录\乾元 Primus"` 退出码 0

## 2. 开始菜单快捷方式

- [ ] 开始菜单「所有应用」中有「乾元 Primus」，图标正确
- [ ] 快捷方式目标为 `<安装目录>\Primus.exe`，起始位置为安装目录（右键 → 打开文件位置 → 属性）
- [ ] 从开始菜单启动后，任务栏图标与快捷方式归为同一组（AppUserModelID `com.primus.desktop`），可固定到任务栏
- [ ] 标准用户登录后同样能看到并启动该快捷方式（按机器安装，公共开始菜单）

## 3. 首次启动

- [ ] 从开始菜单启动，5 秒内出现主窗口，无白屏、无报错对话框
- [ ] 窗口最小尺寸 960×640 可拖到、不能再缩小；最大化 / 还原 / 多显示器缩放（100%、150%）下布局不错位
- [ ] 首次启动引导（如已实现）正常显示，可完成或跳过
- [ ] 关闭窗口后进程退出（任务管理器中无残留 `Primus.exe`）

## 4. Core 进程启动

- [ ] 新建会话 / 发送消息后，任务管理器「详细信息」中出现 `node.exe`，命令行为
      `<安装目录>\resources\runtime\node.exe <安装目录>\resources\agent-core\rpc-entry.js ...`
      （添加「命令行」列查看）
- [ ] `node.exe` 属性 → 数字签名为 OpenJS Foundation，签名有效
- [ ] 关闭会话 / 退出 App 后对应 `node.exe` 退出，无孤儿进程
- [ ] 当前阶段若薄壳尚未接入 Core：本项记「不适用」，以 msi-smoke 的「Core RPC 冒烟」结果代替（需来宾内有 Node.js）

## 5. data 目录普通用户可写

- [ ] `<安装目录>\data` 属性 → 安全：`Users` 组有「修改」权限，应用于「此文件夹、子文件夹和文件」
- [ ] 以**标准用户**登录启动 App，`data` 下生成 `install.json`、`shared\logs\`、`users\<SID>\` 等，无「拒绝访问」
- [ ] 标准用户在 `data` 中可新建 / 修改 / 删除文件；在安装目录根（如 `Primus.exe` 旁）不能写入
- [ ] 两个不同 Windows 用户各自的 `data\users\<SID>\` 互相独立

## 6. WebView2 缺失引导

- [ ] 有 WebView2 运行时的快照：安装日志中引导程序被跳过（`install.log` 中无 `Doing action: InstallWebView2`），App 正常启动
- [ ] 无 WebView2 运行时的快照（`clean-no-webview2`）：安装过程中静默运行内嵌引导程序，装完后
      注册表 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` 的 `pv` 有版本号，App 正常启动
- [ ] 无 WebView2 且**断网**：安装失败并回滚，提示信息为中文、可理解；联网后重装成功
- [ ] 回滚后安装目录、开始菜单快捷方式、「已安装的应用」条目都不残留

## 7. 升级（高版本 MSI 覆盖安装）

- [ ] 先装旧版本，启动一次并新建会话（让 `data` 中有设置与会话数据），在 `data` 中另放一个标记文件
- [ ] 直接运行**高版本** MSI（不先卸载）：顺利完成，「已安装的应用」中只剩一个条目且版本为新版本
- [ ] 安装目录中的程序文件为新版本（`Primus.exe` 属性 → 详细信息 → 文件版本）；旧版本独有的文件已移除
- [ ] **data 保留**：标记文件、设置、会话记录仍在，App 启动后能看到之前的会话
- [ ] 自定义目录（含中文与空格）安装的旧版本升级后仍在原目录，不会改装到默认目录
- [ ] 降级：已装新版本时运行旧版本 MSI，被阻止并显示中文提示「已安装更新版本的乾元 Primus……」

## 8. 修复

- [ ] 删除 `<安装目录>\resources\agent-core\rpc-entry.js`（模拟损坏），然后右键 MSI → 修复，或
      `msiexec /fa <msi> /l*v repair.log`：文件被恢复，App 与 Core 正常工作
- [ ] 修复后 `data` 内容不变，`data` 的 ACL 不变
- [ ] 「设置 → 应用」中不提供「修改」（ARPNOMODIFY），这是预期行为

## 9. 卸载

- [ ] App 运行中卸载：提示关闭程序或自动关闭；完成后无残留 `Primus.exe` / `node.exe` 进程
- [ ] 从「设置 → 应用」卸载成功；静默卸载 `msiexec /x <msi> /qn /l*v uninstall.log` 退出码 0
- [ ] **data 保留**：`<安装目录>\data` 及其中文件仍在（预期行为，便于重装后恢复）
- [ ] 无残留文件：安装目录中除 `data\` 外无其他文件；开始菜单快捷方式已移除
- [ ] 无残留注册：「已安装的应用」中无条目；`HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` 下无 Primus 条目
- [ ] 卸载后重新安装到同一目录：成功，App 能读取保留的 `data`

## 10. SmartScreen 与签名观察

- [ ] 从浏览器下载 MSI（带 Mark of the Web）后运行：记录 SmartScreen 表现（「Windows 已保护你的电脑」/ 直接运行），截图
- [ ] MSI 属性 → 数字签名：签名者 ______，时间戳 ______，签名有效（未签名的开发构建记「未签名」）
- [ ] `Primus.exe` 数字签名同上；`node.exe` 为 OpenJS Foundation 官方签名
- [ ] 可选：`signtool verify /pa /v <文件>` 或 `Get-AuthenticodeSignature <文件>` 输出附在记录中
- [ ] Defender 实时保护开启时安装、启动、发送消息均无拦截或误报

## 12. 日志收集位置

| 日志 | 位置 | 说明 |
| --- | --- | --- |
| MSI 详细日志 | 自行指定：`msiexec ... /l*v <路径>`；msi-smoke 默认 `%TEMP%\primus-msi-smoke\`，经 Reset 脚本执行时为 `C:\PrimusTest\logs\msi-smoke\` | 安装 / 升级 / 修复 / 卸载失败时最关键，搜索 `Return value 3` |
| 冒烟控制台输出 | `C:\PrimusTest\logs\msi-smoke\console.log`（Reset 脚本拉回到宿主机 `vm-logs\<VM>-<时间>\guest-logs\`） | msi-smoke 每一步的检查结果 |
| 薄壳日志 | `<安装目录>\data\shared\logs\app-<日期>.log` | 进程启停、错误、命令耗时（技术方案第 19 章） |
| Core 诊断输出 | `<安装目录>\data\shared\logs\core-<会话>-<日期>.log` | Core 的 stderr |
| 崩溃转储 | `<安装目录>\data\shared\crash\` | App 崩溃时生成 |
| 系统事件 | 事件查看器 → 应用程序（来源 `MsiInstaller`、`Application Error`） | 安装器与进程崩溃的系统记录 |
| WebView2 引导 | `%TEMP%` 下的 `MicrosoftEdgeUpdate*.log`（SYSTEM 运行时在 `C:\Windows\Temp`） | WebView2 安装失败时查看 |

`Reset-PrimusTestVM.ps1` 会自动拉回前两项与 `data\shared\logs`（存在时）；其余手工复制到记录目录。
